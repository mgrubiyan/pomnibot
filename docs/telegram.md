# Telegram

Telegram и MAX используют один backend, HTTPS-домен, PostgreSQL, интерфейс,
OCR и экземпляр `notes.Maker` с общей очередью генерации. Аккаунты платформ
раздельные; наборы, коды приглашений и рейтинги общие. Связывания аккаунтов нет.

## Настройка

1. Создайте отдельного бота через [@BotFather](https://t.me/BotFather), `/newbot`.
2. Укажите его токен в `TG_BOT_TOKEN`. В `APP_ENV=prod` токены Telegram и MAX
   обязательны. В `APP_ENV=local` оба бота отключены, доступен браузерный вход.
3. В BotFather откройте `/mybots` → бот → Bot Settings → Configure Mini App
   и задайте URL `https://<DOMAIN>/` существующего приложения.
4. Через `/setmenubutton` выберите бота, задайте тот же HTTPS URL и подпись
   «Открыть Помнибот». Дополнительно можно настроить Main Mini App в профиле бота.
5. Через `/setcommands` добавьте `start - Начать или продолжить заполнение профиля`
   и `profile - Изменить фамилию и имя`.
6. Запускайте только один polling-процесс для каждого токена. При старте backend
   вызывает `deleteWebhook` без удаления ожидающих обновлений, затем `getUpdates`.
   Отдельные webhook, домен или публичный порт Telegram не нужны.

Настройка Mini App: [официальная документация](https://core.telegram.org/bots/webapps).
Ограничения файлов, polling и `retry_after`:
[Telegram Bot API](https://core.telegram.org/bots/api).

## Профиль и конспекты

В личном чате бот спрашивает фамилию, затем имя: непустой текст после удаления
внешних пробелов, до 100 Unicode-символов на поле. Команды, подписи и вложения
не становятся ответами. `/start` продолжает диалог, `/profile` начинает изменение.
Действующие имя и фамилия сохраняются до окончания обоих шагов, промежуточная
фамилия и шаг хранятся в PostgreSQL. Данные Telegram не перезаписывают введённые имена.

Mini App сначала получает `/api/profile`. До заполнения Telegram-профиля
учебные API возвращают `403` с `code: profile_required`. Форму можно заполнить
в приложении; сохранение сбрасывает незаконченный диалог в боте. Профиль,
заполненный в боте, учитывается при повторной загрузке приложения/профиля.

После заполнения можно присылать документы и фотографии. Из вариантов фото
берётся наибольшее разрешение. Один `media_group_id` собирается после секунды
тишины, не дольше трёх секунд от первого элемента, и становится одним конспектом.
Файлы больше 20 МБ отклоняются, размер проверяется по метаданным и при скачивании.
Напоминания следуют общему расписанию `NOTIFICATION_*`, Telegram-получатель
должен начать личный диалог и заполнить профиль.

## Авторизация и данные

Frontend отправляет исходный SDK `initData` без пересборки:

```http
Authorization: max <MAX initData>
Authorization: tma <Telegram initData>
```

Отдельного заголовка платформы нет. Сервер выбирает один независимый провайдер,
проверяет подпись и разрешает пару `(platform, external_id)` во внутренний
`users.id`. Telegram использует HMAC-SHA-256, срок один час и допустимое
опережение пять минут. Ошибки БД возвращают `500`. Отсутствующая или неверная
авторизация оставляет общий тестовый аккаунт `0`, включая production.

Миграция `00008_platform_identities.sql` сохраняет старые MAX ID, владельцев
наборов и прогресс. Демонстрационные ID `0`, `1..30`, `100001` не получают
идентичности. Новые внутренние ID выдаются последовательностью выше существующих.
Создание идентичности атомарно при одновременном входе через бот и Mini App.
Исторические миграции не меняются; linking и production deployment не выполняются.

## Проверка

```sh
task gen
task lint
POMNIBOT_TEST_DATABASE_URL='postgres://user:password@localhost:5432/pomnibot_test?sslmode=disable' task test
task build
(cd miniapp && bun test)
```

Интеграционные тесты создают изолированные схемы в тестовой PostgreSQL:
проверяют миграцию, конкурентный вход, продолжение диалога после пересоздания
сервиса, совместный набор MAX/Telegram, рейтинг и раздельный прогресс.

Для ручной проверки используйте отдельные тестовые токены MAX и Telegram:

- Telegram: `/start`, фамилия, перезапуск backend, имя; затем `/profile`,
  промежуточная фамилия и завершение формы в Mini App.
- Откройте приложение до заполнения профиля: видна форма, учебные API дают `403`;
  после сохранения доступны наборы и тренировка.
- Пришлите документ, фото, альбом и файл больше 20 МБ; проверьте статусы и очередь
  при одновременной отправке конспектов в MAX и Telegram.
- Вступите из Telegram в набор MAX по коду, ответьте на карточки и проверьте рейтинг.
- Проверьте напоминания, тему, безопасные отступы, открытие по кнопке меню,
  прежние сценарии MAX и браузерный вход без авторизации.

Без отдельных тестовых токенов ручные сценарии в мессенджерах не подтверждены.

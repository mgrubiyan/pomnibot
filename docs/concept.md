# Помнибот — концепция

Хакатон Минобрнауки × MAX, трек «Образовательные решения». Финал 29 октября, Казань.
Документ описывает продукт: зачем он, для кого и что входит в MVP. Технические детали — в README.

---

## 1. Что это

Чат-бот и мини-приложение в MAX. Студент отправляет боту свой конспект (PDF или текст), сервис превращает его в карточки для самопроверки. Карточки проходятся лентой: один вопрос — один экран. Готовым набором можно поделиться с группой по короткому коду.

**Ключевое отличие:** карточки делаются строго из конспекта пользователя, без додумывания. Под каждым ответом показывается цитата из исходного текста.

## 2. Проблема

Первокурсник вуза или колледжа в первом семестре сталкивается с объёмом материала, несопоставимым со школьным, и хочет не просто прочитать конспекты, а проверить себя и закрепить материал до экзамена. Но самопроверяться ему нечем: конспект даёт только текст, готовых вопросов по своему предмету нет, а собрать карточки вручную — часы работы, которых нет при 5–6 предметах. Из-за этого он ограничивается перечитыванием, путает узнавание текста с пониманием и обнаруживает пробелы уже на экзамене.

**Статус:** гипотеза. Нужно подтвердить интервью со студентами и данными по задолженностям на первом курсе. В презентации подтверждённые факты и допущения разделяем.

## 3. Аудитория

Приоритетный сегмент — первокурсники вузов и колледжей. У них самый высокий отсев, нет навыка самостоятельной работы, и именно у них разрыв между «прочитал» и «знаю» максимальный.

## 4. Чем отличаемся от существующего

| Текущий способ | Ограничение | Что даём мы |
|---|---|---|
| Quizlet, Anki | карточки нужно набивать руками | генерация из своего конспекта |
| NotebookLM, ИИ-ассистенты | модель додумывает, доверять нельзя | только то, что есть в тексте, с цитатой |
| перечитывание конспекта | узнавание вместо вспоминания | активная самопроверка |

## 5. Основной сценарий

1. Студент отправляет боту конспект.
2. Сервис режет текст на фрагменты и генерирует карточки по каждому.
3. Студент бегло просматривает карточки, лишние удаляет.
4. Проходит ленту: вопрос → ответ → объяснение с цитатой.
5. В конце видит итог и темы, где ошибался.
6. Делится набором с группой по коду.
7. Через 1 и 3 дня бот напоминает повторить то, где были ошибки.

## 6. Генерация без додумывания

Главное техническое обещание продукта. Как обеспечивается:

- конспект режется на фрагменты, карточка генерируется по одному фрагменту;
- в ответе модели обязательное поле с дословной цитатой из фрагмента;
- если цитата не найдена в исходном тексте — карточка отбрасывается программно;
- неверные варианты ответа берутся из других фрагментов того же конспекта, а не выдумываются;
- температура 0, жёсткая JSON-схема, модель может вернуть пустой результат;
- в интерфейсе под ответом всегда показывается источник;
- кнопка «карточка неверная» — собираем долю брака как метрику.

## 7. Границы MVP

**Must**
- загрузка PDF и текста в бота;
- генерация карточек с цитатой-источником;
- просмотр и удаление лишних карточек;
- лента: вопрос, ответ, объяснение, источник;
- голосовой ответ на карточку;
- личная статистика: где ошибся, что повторить;
- шеринг набора по коду;
- напоминания о повторе.

**Should**
- обезличенная сводка по набору для его владельца;
- режим «одна карточка в чате» без открытия мини-приложения.

**Could**
- экспорт карточек.

**Won't (сознательно не делаем)**
- распознавание рукописных фото;
- видео и внешние ссылки;
- рейтинги, лайки, стрики, соревнование;
- публичный каталог чужих наборов;
- интеграция с ЛМС вуза;
- оценки и выставление баллов.

## 8. Ключевые продуктовые решения

- **Лента конечна.** Дневная порция заканчивается экраном «на сегодня всё». Бесконечный скролл не делаем: повтор через 30 секунд ничего не даёт, интервалы работают на дистанции.
- **Потолок карточек в день не ставим.** Время сессии считается из их количества, примерно 10–15 секунд на карточку.
- **Прогресс сохраняется на каждом ответе.** Ленту можно бросить и вернуться к тому же месту.
- **Мягкий счётчик активности** («4 дня из 7») вместо стрика, который сгорает.
- **Главный экран — «сегодня»**, а не список наборов: продукт сам решает, что показать, иначе человек выбирает лёгкое вместо нужного.

## 9. Разделение бота и мини-приложения

**Бот:** загрузка конспекта, уведомления о готовности, напоминания о повторе, шеринг кода, статусы.
**Мини-приложение:** лента карточек, экран проверки, итоги, список наборов.

## 10. Масштабирование

**Ядро (не меняется):** генерация из документа без додумывания, проверка цитатой, лента, шеринг по коду, модель данных.

**Переменная часть:** тип материала (конспект → методичка → регламент), роль владельца набора (студент → староста → преподаватель), предмет и терминология, язык.

**Путь:** одна группа первокурсников → поток → колледжи СПО → подготовка к аттестациям и корпоративное обучение, где та же задача «проверь себя по документу, ничего не выдумывая».

## 11. Пилот

- **Где:** своя группа или поток перед коллоквиумом либо сессией.
- **Как попадают:** код набора передаётся в чате группы.
- **Метрики:** доля студентов, прошедших набор до конца; доля верных ответов при повторе через неделю; время на подготовку набора карточек по сравнению с ручной; доля карточек, отмеченных как неверные.
- **Дальше:** другие предметы и курсы.

## 12. Риски и допущения

| Риск | Что делаем |
|---|---|
| модель выдумывает | отбрасываем карточки без цитаты из источника |
| LLM тормозит или падает | очередь, статус «генерирую», повтор, запасной провайдер |
| похоже на Quizlet | отличие в генерации из своего конспекта и в проверяемости |
| персональные данные | минимум полей, тестовые данные в демо, явно указано в материалах |
| мини-приложение не работает в веб-версии MAX | проверяем в обеих версиях с самого начала |
| изменения API MAX | сверяемся с актуальной документацией |

**Допущения:** первокурсники готовы тратить 3–5 минут в день на самопроверку; качество генерации из обычного студенческого конспекта достаточно для осмысленных вопросов; код набора — достаточный способ распространения внутри группы.

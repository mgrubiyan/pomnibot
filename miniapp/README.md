# Помнибот — мини-приложение

Фронтенд мини-приложения для мессенджера MAX. Студент проходит карточки,
сделанные ботом из его собственного конспекта, и видит под каждым ответом
цитату из исходного текста.

Продуктовый контекст — [../docs/concept.md](../docs/concept.md).
Макеты экранов — [design/screens.html](design/screens.html), открывается в браузере.
Правила разработки — [CLAUDE.md](CLAUDE.md).

Бэкенд делают другие участники команды, он лежит в `../backend`.

## Запуск

```bash
bun install
bun run dev
```

- `bun run dev` — дев-сервер на :5173
- `bun run build` — сборка (`tsc -b` + vite)
- `bun run lint` — проверка

## Стек

React 19 + TypeScript + Vite на Bun 1.4+, библиотека [@maxhub/max-ui](https://www.npmjs.com/package/@maxhub/max-ui).
Состояние — `useState`, без Redux. Роутера нет.

Все цвета берутся из CSS-переменных MAX UI, поэтому тёмная тема работает
сама. Переменные объявлены на обёртке `<MaxUI>`, она же сбрасывает
`margin` у `body` через проп `resetBody`.

## Экраны и навигация

Роутера нет: текущий экран лежит в `useState` в [src/App.tsx](src/App.tsx).

```
Home ─┬─ «Начать» ─────────────► Feed (все карточки на повтор)
      ├─ тап по набору ───────► SetScreen ─┬─ «Повторить N» ──► Feed (набор)
      │                                    ├─ тап по карточке ─► CardIssue
      │                                    └─ «Удалить набор»
      ├─ «Добавить конспект» ─► AddNote
      └─ «Ввести код набора» ─► JoinSet ───► SetScreen

Feed ── «Карточка неверная» ──► CardIssue ─┬─ «Исправить» ──► CardEdit ──► SetScreen
                                           └─ «Удалить» ────────────────► SetScreen
```

Из ленты выход по кнопке «На главную» на экране «На сегодня всё».
После правки или удаления карточки пользователь попадает на экран набора,
а не обратно в ленту: прохождение при этом прерывается.

| Экран | Файл | Что делает |
|---|---|---|
| Home | [src/screens/Home.tsx](src/screens/Home.tsx) | «На сегодня», список наборов, кнопки добавления |
| SetScreen | [src/screens/SetScreen.tsx](src/screens/SetScreen.tsx) | Состав набора, список карточек, «Почему это работает», запуск и удаление |
| Feed | [src/screens/Feed.tsx](src/screens/Feed.tsx) | Лента карточек: вопрос, разбор, цитата-источник |
| JoinSet | [src/screens/JoinSet.tsx](src/screens/JoinSet.tsx) | Ввод шестизначного кода набора |
| AddNote | [src/screens/AddNote.tsx](src/screens/AddNote.tsx) | Объясняет, что конспект отправляют боту в чат |
| CardIssue | [src/screens/CardIssue.tsx](src/screens/CardIssue.tsx) | Причина, почему карточка плохая: поправить или убрать |
| CardEdit | [src/screens/CardEdit.tsx](src/screens/CardEdit.tsx) | Правка вопроса, ответа и неверных вариантов |

## Виды карточек

Лента поддерживает пять видов, поле `kind` в [src/types.ts](src/types.ts):

- `choice` — выбор из вариантов;
- `boolean` — «Верно» / «Неверно»;
- `input` — ответ текстом, сравнение мягкое: регистр, лишние пробелы и «ё» не важны;
- `flip` — «Показать ответ», дальше самооценка «Знал» / «Не знал»;
- `table` — метод таблиц: термины раскладываются по колонкам тапами,
  без перетаскивания.

У `choice`, `boolean` и `input` есть голосовой ответ. Распознавание сейчас
заглушка на таймере: движок не подключён, экран переключает состояния,
как будто слушает.

## Данные

Всё на моках: [src/mocks.ts](src/mocks.ts), типы в [src/types.ts](src/types.ts).
Реальный API не подключён, эндпоинты не придуманы — каждая загрузка это
функция-заглушка с задержкой (`loadCards`, `loadToday`, `loadSet`,
`findSetByCode`).

В моках четырнадцать карточек: девять по матанализу, три по дискретке
и две по истории. Среди матановских специально неудобные — с вопросом
на шесть строк и с вариантами ответа на три строки, на них проверяется
вёрстка. Числа в наборах (`cardsTotal`, `cardsDue`) сведены с фактическим
количеством карточек, иначе экран набора обещал бы лишнее.

Удаление набора, удаление и правка карточек живут в памяти `App`
до перезагрузки страницы: хранилища браузера использовать нельзя,
бэкенда пока нет. Удаление карточки можно отменить плашкой «Вернуть»,
правку — нет, она перезаписывает предыдущую.

## Отладочные параметры

Состояния, до которых иначе долго кликать, открываются через query:

| Параметр | Что показывает |
|---|---|
| `?fail` | Ошибку сети на главной, экране набора и в ленте |
| `?home=done` | Главную, когда всё повторено |
| `?home=empty` | Главную без наборов |
| `?card=table` | Ленту с одной карточкой этого вида |
| `?card=c9` | Ленту с одной карточкой по id |

Код набора для проверки ввода — `482917`.

## Что дальше

### Экраны, на которые есть макеты

- **Итоги прохождения** («3 · Итоги»). Закрывает пункт Must из концепта
  «личная статистика: где ошибся, что повторить». Лента уже знает тему
  каждой карточки, но результаты ответов сейчас никуда не копятся —
  начинать придётся с этого, тип `AnswerResult` в types.ts под это заведён.
- **Шеринг набора** («4 · Шеринг»). Код показываем, ввод кода уже готов —
  останется вторая половина обмена.
- **Открытый ответ** («2 · Открытый ответ: запись», «разбор ошибки»).
  Сейчас у `input`-карточек простое поле и сравнение строк.
- **Генерация** («5 · Генерация»). Статус сборки карточек из конспекта.

### Экрана нет ни в макетах

- **Выбор другого фрагмента конспекта** при правке карточки. Кнопка на месте,
  но неактивна: нужен список фрагментов исходного текста, а его нет
  ни в макетах, ни в данных.

### Ждёт бэкенда

- Заменить заглушки `loadCards`, `loadToday`, `loadSet`, `findSetByCode`
  на настоящие запросы. Эндпоинты не придуманы — берём у команды бэкенда.
- Сохранение прогресса на каждом ответе: по концепту ленту можно бросить
  и вернуться к тому же месту.
- Настоящие удаление набора, удаление и правка карточек. Сейчас всё это
  живёт в памяти до перезагрузки страницы.
- Отправка причины, по которой карточка помечена неверной. Экран причину
  спрашивает и доводит до `App`, дальше она упирается в TODO, а по концепту
  это метрика доли брака.
- Данные для прогноза повторений на экране набора: удержание в процентах
  и горизонт следующего повтора. Место под него оставлено.

### Ждёт SDK MAX

- Распознавание речи вместо заглушки на таймере.
- Переход в чат с ботом с экрана «Добавить конспект».
- Копирование ссылки на набор при шеринге.

### Технический долг

- `Feed.tsx` разросся: пять видов карточек, голос и разбор в одном файле.
  Когда добавится открытый ответ, стоит разложить по видам карточек.
- Правка карточки прерывает прохождение ленты: экран размонтируется, и место
  в ленте теряется. Чтобы его сохранить, Feed нужно не размонтировать.
- Проверить оба клиента MAX, мобильный и веб. В концепте это отдельный риск,
  а сейчас всё видели только в браузере.
